# 시술별 대표페이지 제작 절차 (playbook)

하위 메뉴 목록 페이지(예: `/nostril/alar-lowering/`)에 **원장님 칼럼 원문**으로 만든 대표페이지 섹션(히어로·원장 이야기·수술 방법·회복·전후사진·FAQ)을 얹는다. 목적은 시술별 검색 노출이다.
완성 예시: `data/landing/nostril-alar-lowering.json` (생성 스크립트 `tools/landing_src/nostril-alar-lowering.py`), `data/landing/nose-hump.json`.

## 절대 원칙
1. **원장님 글은 재작성·요약·윤문 금지.** 데이터에 들어가는 원장님 문장은 칼럼 본문의 줄 범위를 `landing_lib.seg()`로 이어붙여서만 만든다(직접 타이핑 금지). 문장 일부를 건너뛰는 것은 가능하나, 한 문장 안을 고치거나 자르지 않는다.
2. **인용 출처는 원장님 1인칭 칼럼(`/카테고리/하위메뉴/번호/`)만.** `/guide/` 성형 가이드(3인칭 요약)는 인용하지 않는다. 가이드는 "관련 글" 링크로만 쓴다.
3. **원문이 없는 섹션은 지어내지 말고 비우거나 "관련 수술" 링크로 대신한다.** 칼럼에 근거가 없는 수치·효과·기간을 쓰지 않는다.
4. 제작 문구는 최소한으로: 소제목, 히어로 질문형 부제(예: "OO는 어떻게 수술하나요?"), 사진 라벨, 아이콘 정도만. 의료적 주장은 쓰지 않는다.
5. 사용자(빈느님)가 이미 처리하는 동의·의료법 문제는 길게 설명하지 않는다.

## 쓰는 도구
- `python tools/landing_lib.py list|scan|dump|win|grep|images ...` — 칼럼 찾기·줄 번호 보기 (파일 맨 위 설명 참고)
- `python tools/verify_landing_quotes.py data/landing/<파일>.json` — **불일치 0건이어야 함.** 원문과 다르면 종료코드 1.
- `python tools/build_landing.py <cat>-<sub>` — 하위 메뉴 목록 페이지에 대표페이지 적용(재실행해도 안전). 데이터 파일 이름은 `data/landing/{cat}-{sub}.json`.
- 미리보기: `.claude/launch.json`의 `static-journal`(포트 5175)로 `/{cat}/{sub}/` 확인 (PC 폭·모바일 375px, 콘솔 에러, 깨진 이미지, 가로 스크롤 없음).

## 순서
1. `list`/`scan`으로 그 하위 메뉴의 칼럼을 훑고, 설명·정의·원인·방법·회복·부작용·"~가능한가요?" 류 칼럼을 찾는다. `grep`으로 "수술시간", "붓기", "반창고", "실밥", "흉터" 같은 반복 문장을 찾는다.
2. 섹션별 후보를 정한다 (완성 예시와 같은 구성):
   - `features`: 원인/증상/유형 나열 + 한 줄 설명 (한 칼럼에서)
   - `story.blocks`: 원장님 1인칭 설명 3~4블록(정의·원리·분류·진료 철학·경력). 각 블록은 한 칼럼에서
   - `method.steps` 5개: 한 칼럼의 문장 조각. 아이콘은 공용(`sleep ear graft clock tape deviation tip hump fill`) 또는 데이터의 `"icons": {"이름": "<svg 내부 요소 120x120>"}`로 이 페이지 전용 추가. **공용 `tools/build_landing.py`는 고치지 않는다.**
   - `method.note`, `method.pros_cons`: 한계·단점도 원문 그대로 정직하게
   - `recovery.items` 4~5개 (수술 당일/1주/2주/…): 칼럼마다 단계가 다르면 항목별로 출처를 따로 둔다. `recovery.note` 1개
   - `hero.stats` 3개: **원문에 숫자가 있는 사실만.** 조건이 갈리면(예: 한쪽 20분·양쪽 40분) 둘 다 보이게 `from`/`to`와 `extra`(두 번째 칼럼 인용)를 쓴다. 칼럼끼리 수치가 충돌하면 더 최근 글을 쓰고 보고서에 적는다.
   - `before_after.items` 8개: `landing_lib.py images`로 이미지·캡션을 찾아 **캡션을 원문 그대로** 쓴다. 이미지를 내려받아 눈으로 확인하고, 시술 특성에 맞는 각도(코끝 위주면 정면·아래, 매부리·광대면 정면·측면 등)를 고른다. 얼굴이 모자이크된 사진만.
   - `hero.case`: 가장 선명한 정면/전후 한 장, `"layout": "stack"`. `hero.bg_image`는 기존 `images/landing/nose-hump-hero.jpg`를 그대로 쓴다.
   - `logs.items` 6개(대표 칼럼 + 태그), `faq` 4~5개(답변은 원문 그대로), `related` 6개(다른 하위 메뉴 경로)
   - `review_banner_subject`: "OO 수술"처럼 '을/를'이 자연스럽게 붙는 말, `cases_visible`: 9
3. 데이터 생성 스크립트를 `tools/landing_src/{cat}-{sub}.py`로 저장(예시 파일 복사 후 수정) → 실행하면 JSON 생성.
4. `verify_landing_quotes.py` 불일치 0건 확인 → `build_landing.py` → 미리보기.
5. SEO(`seo` 블록, `apply: true`): title은 `핵심키워드 | 설명 | 로코코성형외과 김상호 원장` 형태, description 150자 안팎, h1은 "OO 수술". **같은 키워드를 겨냥한 `/guide/` 글 제목(`guide/posts.json`)과 똑같지 않게** — 대표페이지는 그 시술 전체, 가이드는 특정 질문을 맡는다.
6. 이 브랜치에서 커밋(데이터 JSON, 생성 스크립트, 해당 하위 메뉴 `index.html`만). **push·사이트맵·다른 페이지 수정 금지.**

## 건드리면 안 되는 것
`css/style.css`, `tools/build_landing.py`, `tools/templates.py`, `tools/build_pages.py`, `sitemap.xml`, 다른 페이지의 데이터·HTML, `*.sql`. 공용 코드에 변경이 필요해 보이면 직접 고치지 말고 보고서에 적는다.

## 보고서에 적을 것
- 쓴 칼럼 번호 목록과 섹션별 선택 이유(한 줄씩)
- 칼럼끼리 사실이 충돌한 부분과 처리 방법(예: 한쪽/양쪽 병기)
- 원문이 없어 비우거나 관련 링크로 대신한 섹션
- 제안한 title / h1 / description
- 제작 문구(소제목·질문형 부제·라벨) 목록
- 검증 결과(불일치 0건), 미리보기 확인 항목, 커밋 해시와 브랜치 이름
- 공용 코드에 필요한 변경이 있다면 그 내용

## 알아둘 함정 (비공내리기에서 겪은 것)
- 검증은 문장을 `. `/`? ` 뒤에서 잘라 각 조각이 원문에 그대로 있는지 본다. 문장 끝 마침표를 새로 붙이면 실패할 수 있다(원문이 마침표 없이 끝나는 경우).
- 줄머리의 `- `, `1. ` 번호는 `seg()`가 뗀다. 그래도 "(괄호 설명) - 다음 문장"처럼 중간에 낀 기호가 있으면 그 부분을 건너뛰고 문장 단위로 가져온다.
- 한 칼럼 페이지에 옛 글 여러 편이 이어 붙어 있는 경우가 있다(날짜 줄로 구분). 줄 번호를 꼭 `dump`로 확인한다.
- 원문의 강조 기호(`<< ... >>`)나 말투("~랍니다")도 그대로 둔다.
